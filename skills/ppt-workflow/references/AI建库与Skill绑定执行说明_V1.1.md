# AI建库与Skill绑定执行说明 V1.1

面向使用者：把本文件和末尾的启动指令交给具有本地文件操作能力的AI，让它在你指定的独立目录初始化PPT知识库，并绑定PPT Workflow Skill。

本文件提供建设方法与验收标准，不包含公司资料、客户案例、私有索引或本机路径。它不是已执行的建库程序，也不代表AI已获得访问你全部文件的授权。适用于PPT/PDF内容知识库；其他文档可以扩展字段，不能伪装为幻灯片。

## 1. 建设目标与边界

建立可以持续维护、来源可追溯、可检索的本地私有知识库。公开Skill提供通用方法和设计规范，私有库保存使用者自己的资料；两者用路径配置连接，不把资料塞入Skill目录。

分清四类信息：

- 内容知识：每页应该讲什么、逻辑次序与需要的证据。
- 设计知识：内容如何形成构图、视觉语言与实际验收要求。
- 客户事实：本次客户资料或独立证据支持的数字、条件和成效。
- 过程与反馈：确认、验收、改稿原因以及可提炼的经验。

本说明提供建库执行方法，Skill提供使用规则；目录与生命周期约定一致，维护引擎由宿主提供。读过资料不等于训练了模型；结构可以复用不等于事实已经核验。公开包、私有资料库和实际项目分别保存。

本方法需要AI实际创建目录、索引、配置和使用入口，并用真实检索结果核对绑定；只输出建议目录树不能算建库完成。没有材料时可以初始化空库，但不能虚构已入库或检索通过。

## 2. 开始前确定四个参数

| 参数 | 含义 | 规则 |
| --- | --- | --- |
| WORKSPACE_ROOT | 使用者明确授权的知识工作区 | 优先独立新目录；已有工作区先检查，复用不覆盖 |
| SOURCE_ROOT | 使用者授权读取的资料目录，可暂缺 | 不扫描整个电脑、聊天缓存或其他用户目录 |
| SKILL_SOURCE | 可用的PPT Workflow安装包、已安装路径或公开仓库 | 读取真实文件；不可把不存在的脚本当已可用 |
| FIRST_BATCH | 首批处理范围 | 默认先用一份获授权的PPTX/PDF验证，全部批量入库另按用户范围执行 |

新库默认KB_ROOT为WORKSPACE_ROOT下的`knowledge-base`，INBOX_ROOT为`待入库`，ARCHIVE_ROOT为`已入库`，PROJECT_ROOT为`项目`；实际Skill安装位置根据宿主能力确认。已有库沿用实际路径，并将它们记录到绑定配置。不要把这些名称当作必须修改既有库的理由。

如果使用者未指定WORKSPACE_ROOT，先问一个问题取得目标位置。不能假定当前聊天的工作目录允许被重组。检查同名文件是否已存在；存在则定向读取并合并必要配置，保留有效原内容。不要初始化GitHub、创建定时任务、上传资料、安装无关软件或批量迁移文件。

## 3. 最小目录结构

```text
WORKSPACE_ROOT/
├── 知识库入口.md
├── AGENTS.md                         # 宿主支持时使用；其他宿主用等效规则
├── local-binding.json                # 本地私有配置，不公开
├── 待入库/                           # 尚未正式发布的新材料
├── 已入库/
│   ├── README.md                     # 原始资料与已回流项目的统一导航
│   └── <主骨架ID>_<骨架名称>/         # 已发布外部原件，不复制完整项目
├── 项目/
│   ├── README.md                     # 全部实际项目入口，包括草稿
│   └── <项目名称>/                   # 有实际任务时才创建
├── knowledge-base/
│   ├── README.md
│   ├── manifest.json
│   ├── 原件保留规则.md
│   ├── csv/                          # 以下索引按用途建立，可为空表
│   │   ├── ppt_index.csv
│   │   ├── page_index.csv
│   │   ├── templates.csv
│   │   ├── skeletons.csv
│   │   ├── skeleton_steps.csv
│   │   ├── taxonomy.csv
│   │   ├── feedback.csv
│   │   ├── facts.csv
│   │   └── ingestion_queue.csv
│   ├── pages.jsonl
│   ├── previews/                     # 正式知识页预览，以page_id命名
│   ├── design-standards/
│   └── _ops/
│       ├── config.json
│       ├── state.json
│       ├── records/                  # 候选正文、review与来源证据
│       ├── snapshots/                # 必要索引/配置快照
│       └── _build/                   # 登记的可重建临时输出
└── .agents/skills/ppt-workflow/       # 仅宿主支持时采用
```

不同宿主可能使用其他技能目录，最后一项按实际宿主替换。不要为展示目录结构创建空项目、假交付或虚构页面。

最低必需文件是入口、规则、绑定配置、资料索引、页面索引、正文JSONL、清单和状态。额外CSV应有明确用途；首次可为空表，只写表头。页面浏览HTML和Excel属于可选维护视图，首版不为装饰增加额外管理系统。

**目录职责：**待入库是处理队列，已入库保留正式发布的外部原件，项目保留完整生成成果，knowledge-base保留正式知识资产。新库采用此默认结构；旧库先检查维护工具与引用，再按用户授权适配，不为统一名字批量迁移。归档与项目发现能力须实际实现或验证，不能只创建目录就声称已接通。

## 4. 分类与命名

### 4.1 三层分类

1. 用途/叙事骨架：售前、客户定制、顶层规划、产品、申报、演讲、公司能力等。
2. 行业/业务：允许多标签，不强迫一份资料只能属于一个行业。
3. 页面功能与内容关系：分别记录page_type和layout_type。

`layout_type`描述原页组织形式，不把旧稿版式变成新项目美术默认。新稿按当前设计规范和确认方向设计。

### 4.2 稳定ID

资料ID使用顺序编号，如D001；页面ID为资料ID加物理页码，如D001_P001。模板可用T001，骨架可用S001。这些是格式示例，不是客户资料。

以文件SHA-256判断完全重复；不依靠文件名。改版分配新资料ID，保留旧版与关系，不把近似主题当完全相同内容。页面ID不可因标题修改或重新分类而变化。物理页码包含隐藏页，不能按可见页重新编号。

### 4.3 原件与交付文件

已发布外部原件默认归档到`已入库/<主骨架ID>_<骨架名称>/<原始文件名>`。分类采用已审阅索引suggested_skeleton_id的首个有效主骨架；缺失则暂放待分类，不按标题猜测，多用途保留为索引标签。仅建立有资料的分类，不预建全部空目录。原件内容和资料/页面ID不变，同名目标不得覆盖。项目修订见第9章，项目回流原件留在项目交付目录，不复制到已入库。

## 5. 机器索引的最小数据约定

CSV使用UTF-8（可带BOM），分隔符为逗号；含逗号或换行的字段必须由CSV库正确转义。数组在CSV用`|`分隔，在JSONL使用数组。布尔值在CSV写true/false，在JSON中写真正布尔值。

### 5.1 ppt_index.csv

```csv
doc_id,title,purpose_type,business_tags,applicable_scenarios,suggested_skeleton_id,suggested_storyline,source_file,source_path,sha256,page_count,source_kind,document_status,supersedes_doc_id,derived_from_page_ids,indexed_on
```

`source_path`必须指向可访问的稳定原件；`source_kind`区分外部输入与生成项目，不能据上传入口认定事实独立。`supersedes_doc_id`只有证据支持替代关系时才填写，不根据“V5”等名称猜测整版替代。

### 5.2 page_index.csv：兼容公开检索脚本

```csv
page_id,doc_id,page_no,content_topic,page_type,layout_type,reuse_level,fact_status,source_kind,eligible_for_generation,business_tags,content_summary,source_file,source_path,preview_path,canonical_page_id,derived_from_page_ids,review_status,is_hidden,has_video,document_status,reuse_notes
```

`preview_path`相对KB_ROOT，不能越界。标准目录采用`previews/<page_id>.png`。检索工具所需五个必备列为page_id、doc_id、content_topic、reuse_level、eligible_for_generation；为了可追溯，实际建库同时填写上述完整字段。

复用等级：A为可泛化的清晰组织，B为有价值但需适配的组织，C为仅来源参考、密度/素材/媒体待处理等。等级不是事实认证，也不是美术评分。未复核页默认C且eligible=false；已复核A/B可以成为生成候选，隐藏页、媒体未审页、被替代页不进入默认候选。

事实状态至少支持`source_claim_unverified`、`generated_unverified`、`needs_verification`、`verified`。只有明确独立证据和核验记录才用verified；空白或未核验不转成已核验。

### 5.3 pages.jsonl

每行一个页面对象，保留与索引相同的page_id；至少包含：

```json
{
  "page_id": "D001_P001",
  "doc_id": "D001",
  "page_no": 1,
  "full_text": "",
  "speaker_notes": "",
  "visual_text": "",
  "visual_text_method": "",
  "business_tags": [],
  "evidence_refs": [],
  "derived_from_page_ids": []
}
```

上述为空模板，不是正式页。不能因抽取失败用模型推测填满full_text。图中文字人工补录/OCR放visual_text并注明方法，不覆盖原始抽取文本。JSONL可保存其他索引字段，但共享字段必须一致。

### 5.4 辅助索引

- templates：template_id、page_id、名称、选择理由、适用范围、替换字段、限制。
- skeletons / skeleton_steps：采用公开Skill随包的CSV字段与S001–S010共10套通用骨架；复制的是通用逻辑，不是客户证据。
- taxonomy：dimension、code、label、definition；以用途、业务、页面类型与布局词表为主，按真实内容追加。
- facts：fact_id、主题、来源页面、主张、独立证据、状态、有效期与使用限制。
- feedback：项目、页面、保留/重做/拒绝、具体原因、记录时间。
- queue：item_id、来源文件/路径、sha256、来源类型、状态、资料ID、消息。

先保证表头与实际数据一致，不生成大量空壳报表。没有优选页、事实事项或反馈就保持空表，不能填入别人的真实内容当初始化数据。

## 6. 资料入库：候选与正式发布分开

### 第一步：扫描与登记

只检查使用者授权的SOURCE_ROOT和待入库。对已稳定保存的文件计算SHA-256，识别新增、同内容重复和改版。登记pending，不直接发布。无可处理文件时说明空库或无新增。

### 第二步：抽取与渲染

使用当前宿主实际支持的PPT/PDF解析与渲染工具。抽取逐页文本、备注、页码、隐藏状态和媒体标记，生成候选逐页预览。提取到图片文件不等于完成页面渲染；总览也不替代必要的逐页查看。

在_ops/records/<item_id>保留raw_pages.json、候选previews和review.json。没有对应工具时保持unsupported/failed或待处理，注明缺少解析/渲染能力，不能伪造预览、页数或审阅结果。公开PPT Workflow的kb_search.py只负责检索，不负责解析、发布、归档或清理。

### 第三步：复核与标注

查看实际全文、备注和每页预览，再维护主题、page_type、layout_type、复用等级、标签、事实状态、复用限制和来源。机器建议不能当人工/助手已审阅结果。音视频未播放就不能记录完成媒体审阅。截图里的功能、价格或服务内容不自动成为本方案承诺。

### 第四步：发布验证

确认原件哈希未变化；逐页覆盖连续且页数一致；ID唯一；标签合法；预览存在；引用有效；正文与索引对应；已有Excel修改已同步。保存必要的索引快照，再发布CSV/JSONL/正式预览，更新实际计数。

正式入库失败恢复到发布前索引，不覆盖用户人工内容。候选保持可追溯。先把一份材料走通，扩大批量范围时按使用者授权执行，不为初始化读完全部历史。

### 第五步：正式发布后归档并同步导航

正式发布验证与索引同步成功后，处理本批外部原件：

- 原件在用户授权的工作区待入库中：移动到ARCHIVE_ROOT下的主骨架分类，不额外复制一份，不改写字节。
- 原件来自工作区之外的SOURCE_ROOT：不擅自移动来源文件。按用户明确的保留策略引用稳定来源，或复制一份到ARCHIVE_ROOT并核对哈希；记录原路径及稳定副本路径。后者不能自动删除来源原件。
- 未完成审阅、发布失败、原件已改动、格式不支持或归档冲突：继续留在待处理状态，不标为已归档。同内容重复项不自动删除。

归档时同步ppt_index/page_index、pages.jsonl的来源字段、队列、manifest、可选Excel与现行引用；正文和用户原回复不改写。原件SHA-256、资料/页面/队列ID保持不变。保留旧新路径对应和必要快照；原件及引用核对后才算完成。失败恢复路径和索引，不留下虚假的成功状态。原件旁的同名metadata.json一起保留。

不要假定公开Skill已有归档脚本。复用已验证的宿主维护入口；没有则由执行AI实现这一最小功能，并定向验证。首次验证仅处理授权首批，不迁移其他目录中的历史原件。

已入库/README.md作为统一导航，建议两张简表：原始资料（分类、资料、格式）和已回流项目（项目、分类、收尾状态、定稿入口）。只链接实际文件，不复制项目。回流以正式发布记录为准，知识收尾以knowledge_review和phase_complete为准，清理另看lifecycle.cleanup.status，分开显示。草稿只在全部项目入口显示；主骨架缺失时可按唯一对应的已标注用途作导航分类并说明，不改写索引，无法唯一对应则待分类。没有资料时显示空状态，不虚构统计。归档、回流或状态变化后更新这份现有导航，不叠加重复总览和长篇报告。

## 7. Excel、浏览入口与维护工具

CSV/JSONL作为机器发布数据，Excel作为可选人工维护视图。修改Excel后导入允许编辑的字段，再同步机器索引；资料ID、来源路径、哈希和页码由受控入库维护。发现Excel有未同步修改时暂停覆盖。

首次没有可靠Excel同步工具就先交付CSV/JSONL，不建立一个无法同步的“假维护入口”。浏览页面按需要生成；包含私有资料的浏览页面仍留在私有库。

如使用者需要维护程序，可复用其已经验证的工具；没有则由执行AI实现所需的最小初始化、扫描、候选、发布和校验功能。只读检索优先复用公开Skill现有脚本。报告实际实现命令与依赖，不凭空引用某个只有其他人的电脑上才存在的_ops/kb.py。

默认用使用者提醒触发新增检查，不配置每日任务。代码执行与路径限制以当前宿主授权为准。发布工具需要必要的定向测试；不为了形式运行无关全量测试。

## 8. Skill绑定：配置与实际检索都要完成

公开Skill来源：[PPT Workflow](https://github.com/tsj899764-a11y/ppt-workflow)。可使用已经下载的包；初次下载时记录具体版本或提交，不把远端变化默认为已经升级。本说明作为PPT Workflow的按需参考随Skill分发；只有使用者明确要求建库或绑定时读取并执行，不因安装Skill或制作PPT而自动初始化知识库。Skill提供生产与只读检索规则；新目录初始化和维护适配由执行AI按本说明及私有工作区规则完成。仓库或安装包实际可用版本以读取结果为准，需核对字段和能力兼容性，不把本地候选包当成已发布版本。

### 8.1 安装公开Skill

从实际安装包复制`skills/ppt-workflow`到宿主支持的技能目录。不要把WORKSPACE_ROOT或knowledge-base复制到那里。Codex支持项目级`.agents/skills/`，其他宿主按自己的当前文档配置。安装已有同名Skill时先比较版本，避免覆盖使用者的自定义规则；必要时保留已有版本再按明确授权更新。

宿主不支持自动Skill发现时，明确报告“文件已准备但尚未被宿主发现”；可以让使用者在对话引用该SKILL.md，但不能等同于成功安装。不擅自修改用户全局技能目录或应用设置。

### 8.2 local-binding.json只放私有工作区

```json
{
  "schema_version": "1.1",
  "skill_name": "ppt-workflow",
  "skill_version": "",
  "workspace_root": "",
  "kb_root": "",
  "inbox_root": "",
  "archive_root": "",
  "project_root": "",
  "skill_root": "",
  "binding_status": "unconfigured",
  "verified_on": "",
  "verification": {
    "query": "",
    "expected_page_ids": [],
    "actual_page_ids": [],
    "read_only_verified": false
  }
}
```

将空字符串填成真实、可访问的位置。这个文件是本方法新增的本地接入约定，**现有PPT Workflow脚本不会自动读取它**。绑定要通过下一步项目规则显式传入--kb，不能只写配置就宣称生效。

### 8.3 项目规则负责把路径传给Skill

在工作区AGENTS.md或宿主等效项目指令中写入以下规则，替换实际路径；保留已有项目规则：

> 实际项目使用本地私有知识库。先读取本工作区local-binding.json；从中取得kb_root、inbox_root、archive_root、project_root和skill_root，核对实际目录及用户授权。检索时调用skill_root下的scripts/kb_search.py，显式传入--kb kb_root。不得在真实任务中把无参数返回的虚构演示库当作私有库。未配置或路径失效时报告具体问题，不改读其他目录。检索输出只用于当前私有工作，不写入公开Skill目录。项目输出保存到project_root/<项目名称>；已发布外部原件按受控归档规则进入archive_root，完整项目不复制过去；继续执行内容确认、完整HTML确认和最终采用确认的规则。

项目规则的位置和宿主加载效果须实际核对；不同宿主不保证识别AGENTS.md。另一种方式是使用者在每次请求里提供库路径，或在私有运行环境设置PPT_KB_ROOT。不要为方便把个人路径硬编码进公开SKILL.md或脚本。

### 8.4 实际绑定验收

从一份已经真实复核发布的首批材料中选择一个可检索A/B级页及其主题。用库路径执行：

```text
python3 <skill_root>/scripts/kb_search.py "实际页面主题关键词" --kb <kb_root> --doc-id <实际资料ID> --limit 3 --include-text
```

检查：

1. library_mode为user_private_library，fictional_demo为false。
2. actual_page_ids包含预期的真实页面ID。
3. 标题、物理页码、来源与正文对应首批材料，未虚构事实认证。
4. 检索前后机器索引哈希相同，且未往Skill目录写入检索结果。
5. 宿主能读取Skill入口，实际任务遵循内容确认后设计、HTML确认后PPTX的顺序。

前四项验证只读数据接入，第五项验证宿主技能使用；两者不能互相替代。成功后填binding_status=verified及实测记录。

没有材料或没有符合候选条件的页时，使用configured_empty或configured_no_eligible_pages并说明原因，不为了验证强行把C级改成A/B或植入虚构案例。可验证空结果与目录访问，但不能声称真实检索通过。需要复制虚构数据测试工具时，使用隔离临时目录并标fictional_demo，不能加入正式库。

## 9. 实际项目生产与回流

首次实际项目才创建PROJECT_ROOT/<项目名>。同一实质版本集中保存：

```text
项目/<项目名称>/
├── project_manifest.json
├── 输入资料/                         # 独有输入；共享稳定原件用路径＋哈希
├── 项目反馈.jsonl                    # 有反馈时维护
├── v1.0/
│   ├── 内容稿.md
│   ├── 视觉基准.json                   # 本版本整套视觉基准
│   ├── 页面记录.json
│   ├── HTML/                         # HTML、依赖素材、HTML预览PDF
│   └── 交付/                         # PPTX、成品逐页预览
└── _build/                           # 过程渲染和构建文件
```

生产顺序：明确需求与授权资料 → 检索内容和骨架 → 编排整套与逐页内容 → 用户确认内容 → 视觉基准与完整HTML → 浏览器逐页检查并提交 → 用户确认HTML → 可编辑PPTX → 独立渲染验收 → 交付与反馈 → 用户最终采用 → 知识回流与收尾。

确认集中到project_manifest.json的confirmations.records，分别记录content、html、final_adoption；每条已确认记录保留版本、文件、范围、用户回复依据，以及实际可获得的时间和摘要。已有approvals或独立确认文件按历史来源读取，不补造批准、不再建重复记录体系。助手自检、成功导出、沉默和等待时长不能替代确认。

页面记录复用当前逐页设计模板：page_no、page_type、visual_baseline、layout、visual_subject、visual_treatment、design_reason、asset_declarations、content_reference_page_ids、input_evidence、fact_status。共享设计信息维护一次；acceptance_by_target.html/pptx分别记录九项检查、实际渲染与查看状态、文件版本摘要和结果。display_preview只作成品展示入口，不替换历史验收证据。

错字或兼容性小修订在当前目录另存文件，如项目_v1.0.1.pptx；实质内容或设计变化才新建v1.1等目录并返回相应确认节点。未变范围沿用有效批准。批准文件及历史HTML依赖素材禁止覆盖，素材变化另存。current_final指向已有定稿交付，不重复复制一套定稿归档；路径相对实际项目目录。

共用输入以稳定路径、SHA-256及定位引用，不跨项目反复复制；外部输入无法稳定保留时保存一份必要独立原件并说明。移动已有项目需同步来源、确认和现行引用，保证回流扫描、反馈去重与清理能发现新位置，不能只搬目录。保留原反馈身份，路径变化不得生成重复反馈。

公开Skill提供通用规则、公开设计规范、10套骨架与只读检索，不提供PPT导出、浏览器、渲染、发布或归档引擎。宿主执行能力必须实际可用；缺失时记录未完成，不能用整页截图冒充可编辑PPT。

用户最终采用后标final_confirmed，按既有机制提炼、比较、去重和验证知识；无新增写none_new及依据，未验证保持pending。正式发布的生成稿标generated_project，事实默认generated_unverified；不能靠生成稿互证。生成项目回流引用项目交付原件，不复制到已入库。回流已发布与收尾完成分开记录并同步统一导航；制作阶段确认不是最终采用或公开授权。

## 10. 生命周期、预览与清理

| 类别 | 处理原则 |
| --- | --- |
| 核心知识 | 规则、字段与正式规范长期保留，不自动删除 |
| 可复用知识资产 | 正式内容、预览、骨架与经验保留来源及验证依据 |
| 项目交付 | 保留最终及已确认旧版、必要输入、关键决策与确认/验收结论 |
| 临时过程文件 | 明确临时、可重建、阶段完成且无保护引用才可按既有机制清理 |

HTML预览PDF默认由当前HTML导出，版本及页面对应，存HTML目录，供整套审阅、批注和转发；已用于确认或必要证据的PDF保留。成品预览PDF默认不生成，用户要求PDF交付、离线阅读或打印时从对应PPTX导出。PDF不能替代HTML浏览器检查或PPTX独立逐页渲染验收。

制作和验收期间可保留两套渲染图片，临时输出默认放项目_build。定稿回流收尾后，常规逐页PNG保留交付/预览中的一套PPTX实际渲染图片；HTML保留页面、依赖素材和预览PDF。普通展示引用可改为成品预览并标明PPTX来源，HTML背景/局部素材不得用整页截图替代，必要HTML验收图、批注或问题对比单独保留。

只有用户最终采用、实际验收完成、必要成果与依据保全、knowledge_review为completed或有依据的none_new，才设lifecycle.phase_complete=true及对应临时项阶段完成。未完成收尾的项目不提前清理；不把回流已发布等同于收尾已完成。

候选抽取、review、来源哈希、正式知识页预览、发布记录及必要快照不作为普通缓存。目录名、旧版本号或相似文件名不是删除依据。收尾满足前提后，由执行AI主动评估当前项目、复核清单并执行已获授权的安全临时项，不等使用者再次提醒，也不能停在生成清单就宣称已完成清理。已有宿主机制直接复用；缺少执行工具或删除授权时只列清单并记录具体缺口，不另造清理体系、不扩大删除权限。

自动项仅限_build内逐文件登记temporary=true、rebuildable=true、phase_complete=true，且有效rebuild_inputs/rebuild_method、无受保护引用的普通文件；程序确认路径无越界/符号链接、文件未变化，默认预演，执行需显式参数。工具更严格的保护优先，PDF默认受保护时不能靠临时标记绕过。

未登记的PNG/PDF或其他文件先输出具体清单，经使用者确认范围后处理；不能搬入_build、移除保护引用或改标临时来绕过确认。不递归删目录。清理保留原路径、摘要、授权依据和结果，记录已清理预览的真实状态，不用PPTX截图冒充旧HTML证据。移入废纸篓不等于已释放磁盘容量。仅用户提醒或项目收尾触发，不设置定时任务。

清理只处理当前项目，不顺带处理其他项目或共享目录。若宿主支持项目范围参数，在生成清单与执行时传入同一实际项目；未支持时必须另行核实范围，不能凭空假定已隔离。

将结果并入现有project_manifest.json的lifecycle.cleanup，至少记录status、实际删除数量/字节、累计释放量、清理前后项目及_build体积。状态区分not_assessed、planned、pending_confirmation、needs_attention、not_ready、completed；phase_complete表示知识收尾前提，不代表文件已清理。剩余候选需要使用者决定时维持pending_confirmation；全部处理或明确保留、无待决项后才记completed，无可删文件如实记零删除。复用同一清单与日志，不叠加例行总结。

候选PPT不因曾经检查而永久保留，也不因文件名含“候选”就自动删除。已确认旧交付、关键证据与原件继续受保护；需要清理时先给具体清单，说明丢失旧可编辑文件或原截图的影响。共用原件去重必须保留一份稳定、哈希一致的原件并同步引用；经明确批准删除后记录旧路径、原哈希和实际文件状态，不制造仍可打开或可恢复的假记录。制作阶段关注字体嵌入、重复导出和过程截图体积，不能为瘦身改写已确认交付或省略实际验收。

## 11. 私有与公开隔离

local-binding.json、原件、真实索引/正文、预览、项目输入与交付、反馈、日志、快照保持私有。公开Skill只能放通用方法、核准可再分发的规范/工具、授权素材和虚构示例。

公开包从明确文件白名单生成，不直接公开整个工作区或既有Git历史。脱敏名称不等于彻底去除项目特征，也不等于获得第三方图片/模板的再分发权限。经验进入私有库不等于可以公开。

在局部.gitignore加入私有目录与配置只是辅助，不替代白名单和发布审查；不修改用户全局Git配置。任何公开上传都是独立任务，需使用者明确指定发布范围与目的地。本次建库任务不包含GitHub发布。

本地只读脚本不联网不等于宿主模型不处理资料。使用者应按自己的数据要求选择宿主和模型服务；本方法不声称零泄漏或自动安全认证。

## 12. 建库交付与最小验收

执行AI最后交付：

- 真实可用的目录与入口文件；初始库可为空，但实际数量如实记录。
- 与实际数据一致的CSV/JSONL、受控分类及计数清单。
- 已安装或明确尚未安装的Skill位置、版本，以及本地绑定配置与项目规则。
- 首份资料若有处理：资料ID、页数、实际审阅范围、原件哈希与来源保留位置。
- 一条可直接使用的检索/制作请求；给出绑定状态与验收结果。
- 仅列实际缺项，例如缺少渲染工具、Excel同步未实现、无可检索材料或宿主未发现Skill。

一轮定向验证检查目录、必要表头、ID和页数、引用/预览、来源哈希、只读检索和绑定模式。未完成项不能描述为已完成。首版目标是实际初始化并打通一份材料与Skill检索，不要求读完全部资料、建向量数据库或制作完整PPT。
