# PPT Workflow

### 把项目资料，变成逻辑清楚、设计统一、可以编辑的商业 PPT。

给 AI 一份资料，距离一份能拿去汇报的 PPT，还有内容编排、页面设计、事实核对和成品验收。

**PPT Workflow 把这些工作组织成一套可以执行的流程：先确认内容，再确认完整 HTML 设计，最后制作可编辑的 PowerPoint。**

你可以直接用自己的材料开始，也可以连接本地私有知识库，让已有方案、内容资产和改稿经验参与后续制作。

当前版本：**0.2.2** · [开始使用](#开始使用) · [制作流程](#从资料到交付每一步都看得见) · [10 套骨架](#内置-10-套商业-ppt-骨架)

## 从资料到交付，每一步都看得见

**提供资料 → 确认内容 → 确认 HTML → 制作可编辑 PPTX → 验收与定稿**

### ① 先把整套逻辑讲清楚

根据汇报对象、使用场景和项目目标，选择适合的叙事骨架，编排章节与逐页内容。

你先审阅整套逻辑、每页结论和资料依据。内容确认后，再进入设计。

**这一阶段，你会得到：整套大纲与逐页内容稿。**

### ② 先看到完整设计，再进入 PowerPoint

将确认后的内容制作成完整 HTML 预览。标题、图表、流程、架构和场景视觉在同一套设计语言下呈现。

AI 在浏览器中逐页检查，你可以审阅整套页面并提出修改。当前 HTML 版本经你确认后，再制作 PPTX。

**这一阶段，你会得到：可在浏览器查看的完整设计预览。**

### ③ 交付能继续修改的 PPT

按照已确认的 HTML 制作可编辑 PPTX，核心文字与图形保留编辑能力。

PPTX 需要独立渲染检查，并与批准的 HTML 对照，修正溢出、遮挡、缺失和明显的还原问题。

**这一阶段，你会得到：可编辑 PPTX，以及实际完成情况对应的验收记录。**

## 用内容决定版式，用规范保持质感

PPT Workflow 包含三份完整设计规范，覆盖视觉方向、内容驱动设计和执行验收：高级视觉设计 V2.0、执行验收 V1.2、内容驱动设计方法 V1.0 公开版。

它指导 AI 根据内容关系选择表达方式：

- 并列观点，用有主次的卡片组合。
- 层级关系，用清晰的分层架构。
- 建设步骤，用有阅读顺序的流程。
- 关键价值，用明确的视觉焦点呈现。
- 内容过多，先整理结构或拆页。

整套保持配色、字体、图标和组件统一，页面构图随内容变化。3D、渐变和光影按需使用，为信息服务。

完整规范在内容批准后的设计阶段读取，入口见 [设计说明](skills/ppt-workflow/references/design.md)。

## 内置 10 套商业 PPT 骨架

从不同任务的叙事逻辑出发，组织内容顺序：

| 方案与规划 | 产品与能力 | 专题与汇报 |
| --- | --- | --- |
| 标准行业售前 | 平台产品介绍 | 专项申报与立项 |
| 客户定制售前 | 公司能力介绍 | 峰会专题演讲 |
| 顶层规划咨询 | 安全运营服务售前 | 经营与业务发展规划 |
| AI 数据治理专题售前 | | |

S001–S010 每套骨架提供可调整的章节逻辑、逐步写作任务和页数预算，并附机器可读 CSV。实际页数和内容深度，根据你的材料、汇报时长与决策目标确定。

## 没有知识库，也能直接开始

安装 Skill 后，提供当前项目资料即可使用。

AI 会结合内置骨架与设计规范完成内容编排和后续制作。缺少事实依据的部分会明确标注，等待补充或核实。

**不需要先搭建一套知识库，才能做第一份 PPT。** 无库时不会自动创建知识库；没有回流目标也不阻止项目交付。

## 有私有知识库，可以积累自己的方法与经验

连接本地知识库后，可以按需检索历史方案、内容参考页和项目反馈，并保留来源定位。

项目最终定稿后，再识别本次可复用的内容、结构和设计经验，经去重与验证后归入已有知识资产。入库与维护需使用你自己的私有机制。

**持续积累的是可检索、可追溯的知识资产。** 这需要实际整理与维护，不代表模型会自动训练或记住文件夹中的所有资料。

公开 Skill 提供通用方法、规范、模板与只读检索工具；你的公司资料、客户材料和项目成果由私有库单独管理。本包不包含真实公司 PPT、客户案例、私有索引或预览，也不自动上传或发布内容。

## 开始使用

将本仓库的 `skills/ppt-workflow` 整个文件夹复制到支持 Agent Skills 的宿主技能目录，具体位置以宿主当前官方说明为准。此版本通过 GitHub 分发，尚未打包成插件。自己的资料库单独保存，不放入 Skill 目录。

然后向 AI 提供资料，并提出任务：

> 使用 $ppt-workflow，根据我提供的资料，制作一份面向客户管理层的20页售前方案。先提交整套逻辑和逐页内容，等我确认后再制作完整HTML设计预览；HTML确认后，再制作可编辑PPTX。缺少依据的内容请明确标注。

也可以先从更小的任务开始：

> 使用 $ppt-workflow，帮我判断这份材料适合什么汇报骨架，并整理逐页内容，暂不进入设计。

已有私有知识库时：

> 使用 $ppt-workflow，检索我指定的私有知识库，找出适合本项目的内容参考，保留来源页面ID。资料库路径由我单独提供。

## 使用条件与能力范围

PPT Workflow 是一套指导 AI 执行任务的 Skill。HTML 制作、浏览器检查、PPTX 生成和渲染，需要运行它的 AI 环境提供相应工具；本仓库不附带完整的制作与渲染引擎。工具缺失或未实际检查时，需要如实说明未完成的步骤。

本地知识库为可选项。内置只读检索工具支持 Python 3.10 及以上版本，使用标准库，无额外依赖；未配置私有库时，检索演示数据仅用于说明用法。

### 只读检索

从本包根目录试用：

```bash
python3 skills/ppt-workflow/scripts/kb_search.py "运营" --include-text
```

连接私有库使用 `--kb` 或 `PPT_KB_ROOT`，详见 [知识库接入说明](skills/ppt-workflow/references/library.md)。检索支持主题、摘要和标签匹配，A/B 候选过滤、规范页去重，以及命中页正文读取。

本包不支持全文向量检索、自动解析 PPT、自动发布入库、自动原件归档或清理。脚本不联网；宿主模型服务如何处理输入由其环境决定。本包不提供“零泄漏”保证。

### 项目保存与预览

同一实质版本集中保存内容、HTML 和交付；确认记录合入项目清单，HTML/PPTX 验收分别记录。小修订在当前版本另存文件，实质变化另建版本目录，定稿不重复复制归档。

默认生成 HTML 预览 PDF，成品预览 PDF 按需生成。定稿、验收及回流收尾完成后，常规逐页 PNG 保留一套 PPTX 成品预览，必要历史证据和依赖素材继续保留。清理复用宿主机制，未登记文件先列具体清单确认。

有库时，默认工作区分为待入库、按骨架归档的已入库、实际项目容器与正式知识库；已有布局优先。目录说明链接外部原件与已回流项目，发布与收尾状态分开。具体规则见 [生命周期说明](skills/ppt-workflow/references/lifecycle.md)。独立建库执行说明不附在本 Skill 内。

### 公开包维护与许可

发行包由tools/build_release.py中的明确文件白名单生成，拒绝白名单路径中的符号链接，检查常见个人路径和凭据样式。扫描只是辅助，不能判断全部商业秘密或再分发权限。tests/test_tools.py使用临时虚构数据测试检索、过滤、去重和安全边界。

```bash
python3 tests/test_tools.py
python3 tools/build_release.py --output ../ppt-workflow-v0.2.2.zip
```
