# PPT内容驱动设计方法 V1.0（公开版）

本版保留内容到构图、素材准备、按需视觉探索、五维评审及HTML/PPTX实现边界；不包含真实项目案例或私有库溯源路径。

## 适用范围与优先级

适用于售前方案、论证报告、管理层汇报、产品介绍等PPT及其HTML设计预览。网页应用、宣传动画、视频音频管线不纳入本次转化。

用户明确项目要求优先；[视觉设计V2.0](AI_PPT_高级视觉设计知识库_MVP_V2.0.md)继续决定视觉基准，[执行验收V1.2](PPT视觉执行与验收_V1.2.md)继续规定素材声明、九项验收与确认边界。本方法补充操作判断，发生冲突时服从上述当前规范。原作者的原文只作来源资料，不成为另一套生产指令。

制作顺序保持：内容与逻辑 → 用户确认内容 → 本地方法推导设计与HTML → 用户确认完整HTML → 可编辑PPTX与独立验收。样页选择不能替代整套HTML确认；不新增固定审批、数据库、评分系统或定时任务。

## PDM-01｜先确定页面的表达任务

每页先明确五个问题，简洁记入既有页面记录的设计理由、主体或备注，不另写长篇报告：

1. **叙事角色**：说明背景、建立目标、解释关系、呈现证据，还是促成下一步判断？
2. **观众与阅读距离**：管理层投屏、会议桌阅览或个人阅读？字号和密度按真实画布及可读性调整。
3. **表达气质**：项目需要稳健、权威、清晰、亲和或较强展示感？在已确定的基准内处理。
4. **内容容量**：核心信息、必要证据及边界能否放下？先重组分区；必要时在用户页数与确认范围内调整，不能删除证据或缩成难读小字。
5. **内容特有的结构或视觉主体**：层级、双线汇合、责任分工、真实场景、产品界面或核心指标中，什么最能帮助理解？不为每页强造隐喻。

一个页面应有明确表达任务和主要视觉焦点；表格与架构可以包含多项信息，不机械限制成三个要点或一个固定版式。

## PDM-02｜从内容关系选择构图

| 内容关系 | 首选表达 | 需要说清楚 | 误用检查 |
| --- | --- | --- | --- |
| 层级支撑 | 分层架构、树形结构 | 上下层承接、共同支撑及真实依赖 | 不把架构层级编号当作实施步骤 |
| 先后动作 | 横向或纵向流程 | 起点、动作、交接、结束条件 | 不能给并列职责凭空加顺序 |
| 多条业务汇合 | 双入口或泳道＋共用流程 | 各入口不同之处、共享能力、责任交接 | 不让所有入口强制经过不适用的研判环节 |
| 并列角色与职责 | 职责矩阵、对照表或清晰分区 | 谁做什么、产生什么、谁负责确认 | 不画成四步流程，不把辅助建议画成自动审批 |
| 多方关联 | 中心关联、节点连接 | 关系类型和连接依据 | 没有依据就不加连线或箭头 |
| 对比或路线选择 | 同口径双栏、对比表 | 范围、成本、价值、限制及适用条件 | 指标、单位与统计期必须可比 |
| 闭环反馈 | 路径＋反馈连接 | 发现、处理、复核、归档与反馈去向 | 只有业务确实返回前序时才画循环 |
| 数据与规模 | 大数字、原生图表、对齐表格 | 单位、基期、范围、来源和数字属性 | 目标、预测、示例与实测不可混用 |
| 价值与判断条件 | 预期价值＋核验方式或推进条件 | 价值如何发生、如何核验、前提是什么 | 不能只放收益卖点，省略决定成立的条件 |

以上是选择工具，不是每套必须覆盖的模板。布局可以组合；保持整套风格统一，让密度、视觉主体和构图随内容变化，避免连续机械重复卡片。

## PDM-03｜素材准备先于精细排版

先判断素材是内容证据、表达主体还是装饰，再确认是否可用：

- 客户已有Logo、场景、产品图、系统界面及指定参考，先核实来源、版本、比例与适用范围。
- 架构、流程、职责和真实数据优先用可编辑对象；业务图不会因为缺少装饰图而停工。
- 需要真实场景或产品身份时，先获取合适素材，核实授权、清晰度和裁切空间后再确定精细构图。暂缺时明确标注待补，不用通用图冒充真实项目。
- 图标采用统一专业体系；不默认每个标题配一个图标。AI场景图按现有规范标识概念身份。
- 装饰素材只在有明确表达作用时使用；不因图像数量、3D数量或“显得高级”而增加内容。

素材信息写入现有素材记录或逐页依据，不强制新建品牌协议文件。复核关键素材即可；没有新缺陷不重复取图、截图或查授权。事实核验与外部素材来源核查仍按实际需要执行，停止外部技能调用不等于停止必要的事实检索。

## PDM-04｜建立统一而有变化的视觉语言

统一配色、字体层级、图标、边框、圆角、光影和共同页头页尾；参数服从V2.0及实际项目要求。按真实画布换算，不照搬外部配方字号、字体或颜色。

整套需要疏密和重心变化。通过构图、真实素材和信息组织形成识别度，不默认添加英文副题、数字徽标、章节碎片或全页渐变。不能把历史知识库中的其他项目事实或样式直接套入当前客户。

## PDM-05｜多方向视觉探索按需启用

**用途：**帮助用户在几个合理解释中选择方向，降低整套返工成本。

**触发：**用户要求多个方向；视觉方向不明确；重要新项目存在明显不同的合理表达；用户对当前设计不满意且原因涉及整体方向。

**可直接沿用：**本次已明确选定方向或要求沿用具体模板；已批准方向后的局部改稿；导出、转格式、截图、纯文字修正。不能把品牌名或一个宽泛风格词自动当作足够具体的方向，也不强制所有新项目三版。

**最小探索范围：**默认2–3个方向，每个方向选2页代表样稿，例如“封面＋架构”或“数据页＋结论页”。样稿内容、尺寸和已确认事实一致；区别应体现构图、重点、素材处理或信息密度。只换颜色不能自动算成有效探索。

探索发生在内容确认后的HTML设计阶段。提供可见样稿及一句取舍理由，用户需要选择时等待明确回复；不以沉默、等待时间或助手偏好认定用户已选定。将实际选择和版本记入既有流程确认文件或项目视觉基准。用户选定方向后再完成整套HTML，完整HTML仍需单独确认。

不制作多套完整PPT来选择方向，不默认启用多代理。预计超过用户验证预算或需要扩大范围时，按当前项目规则处理。未经用户要求不反复探索已确认方向。

## PDM-06｜概念检查＋完整五维设计评审

**前置问题：**“这页或这套报告希望观众理解或决定什么，当前构图是否支持？”先检查表达目的，避免只有风格没有有效信息。没有独特艺术隐喻不等于不合格；清晰专业的矩阵、标准架构与必要复用均可成立。

| 五维 | 判断问题 | 与九项验收的衔接 |
| --- | --- | --- |
| 风格与品牌一致性 | 符合客户身份、使用场景和批准方向吗？有无来源不符或风格混杂？ | 风格一致、素材真实 |
| 视觉层级 | 观众能先找到核心信息，再读必要证据和边界吗？ | 构图与焦点、信息层次、排版与留白 |
| 执行质量 | 字体、对齐、间距、图标、裁切及光影是否协调？ | 视觉质感、排版与留白、渲染完整 |
| 表达有效性 | 架构、流程、数据与素材是否帮助理解业务？有无装饰抢占内容？ | 逻辑可读、构图与焦点、素材真实 |
| 内容适配与识别度 | 是否为这份内容选择了合适结构？是否机械套用通用模板？ | 页面变化、逻辑可读、构图与焦点 |

**执行方式：**在已有整体视觉检查中覆盖五维一次，关注整套一致性和代表页、密集页、关键决策页；逐页九项检查仍覆盖所有页。两者共享同一轮实际渲染证据，不新增一轮截图或重复检验。

**简洁输出：**记录检查版本与页面范围、值得保留的处理、必须修复的实际问题、留给用户判断的主观偏好。每个问题指出页码、实际现象及影响，不能只写“高级感不足”。可在现有项目视觉基准的design_review字段或验收简记中记录。

默认不写每页0–10分、总分、雷达图或长篇报告。用户明确需要评分时再给分项依据，不把助手分数当作客观认证。管理层报告优先清晰、有效、专业，不为创新性强行改动已成立的版式。

修复服从当前验证预算：实际硬性缺陷修正后复查受影响页；没有明确缺陷不开展新的主观美化循环。审美偏好交由用户决定，助手评审不替代内容、完整HTML或最终采用确认。

## PDM-07｜HTML与PPTX的实现边界

以HTML表达完整设计，再按批准版本制作PPTX。核心文字、表格、架构、流程及数据图保留可编辑性；图片作为独立素材，不把整页截图冒充可编辑PPT。

浏览器与PPT渲染环境不同：文字断行、表格背景、字体、圆角和图片裁切均可能需要兼容处理。修正应保持已批准内容与设计范围，改后只复查受影响页面；实质变化回对应确认节点。图标、照片及背景不要求转换成数据图形。

单文件或分页HTML按交付环境和维护成本选择，保证样式隔离、资源可读、翻页及整体预览可用。不依赖外部技能的播放器、导出脚本、联网字体或固定工程架构；不改变浏览器安全策略，不把本地HTTP服务设为默认前置条件。制作与渲染采用当前环境可用且受支持的工具；本方法不取代文件格式技能的技术要求。
