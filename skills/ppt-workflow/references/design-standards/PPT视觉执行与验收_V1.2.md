# PPT 视觉执行与验收规范 V1.2

修订日期：2026-10-09。统一默认采用V2.0；按用户要求增加内容确认与HTML设计确认两个必经节点，九项验收要求继续适用。

> **定位：**《AI PPT 高级视觉设计知识库 MVP V2.0》的轻量操作层。  
> **适用范围：**现有 PPT 知识库生成的全部演示文稿。  
> **职责边界：**历史 PPT 提供内容参考；V2.0 负责视觉设计；本文件规定参数裁决、素材声明、逐页设计依据、用户确认节点与成品验收。两处确认嵌入现有生产流程，内容知识库职责保持不变。

## 一、执行原则

1. **先保证清楚，再追求精美。**视觉效果服务于信息表达；不以装饰数量、3D 数量判断设计水平。
2. **一套 PPT 使用一套视觉基准。**同一份演示文稿统一基础配色、字体、图标与组件风格；布局可随页面内容变化。
3. **历史 PPT 不作为默认美术模板。**可借鉴其业务内容与页面应表达的信息，不直接继承陈旧排版、配色或低质量素材。
4. **以真实渲染结果验收。**仅有设计描述、代码或源文件，不算完成视觉检查。
5. **不编造素材与验证结果。**未确认来源、授权、产品真实性或未完成渲染检查时，必须如实标记。

## 生产流程中的两处用户确认

**内容编排完成后，必须由用户确认，才能进入视觉基准选择和逐页设计。**

提交可审阅的整套逻辑与逐页内容，至少包含章节顺序、总页数、每页标题、核心信息、正文要点、内容来源及待补事实。展示具体版本，明确等待用户确认。用户提出修改时先修订内容并再次提交，不能自行认定已通过。

**逐页设计先生成完整HTML预览，必须由用户确认，才能制作可编辑PPTX。**

HTML覆盖全部计划页面及实际文字、配色、构图、图片和图表。先在浏览器实际渲染、逐页检查并修正，再提交用户确认。HTML确认前不创建PPTX候选稿或草稿，不以先生成PPT再包装为HTML的方式越过确认节点。用户要求修改时先改HTML，更新版本并重新提交。

确认来自用户对相应具体版本的明确回复，记录被确认文件、版本、确认时间与回复依据。助手自检通过、文件成功导出、用户未回复或经过一段时间，均不能替代用户确认。无需强制用户使用固定口令，但确认对象和授权阶段必须清楚。

用户确认HTML后，按该版本制作可编辑PPTX，优先原生文字、架构、流程、图表等对象；整页截图不能作为可编辑PPT交付。PPTX仍须独立渲染验收，并与批准HTML核对页序、内容及视觉。必要的兼容性修复可在已批准设计范围内完成；实质修改内容或设计时，回到对应确认节点，仅复核受影响版本与范围，不重复索取已有效的确认。

两处确认的记录与助手视觉验收记录分开。项目定稿回流继续遵循原有用户最终采用确认规则。

## 二、视觉参数与优先级

**统一以 V2.0 为默认视觉规范。** 在整套 PPT 级别确定配色、字体、图标、组件与光影，并保持一致。

| 参数 | V2.0 默认值或要求 |
|---|---|
| 主色 | `#1769FF` |
| 深色／标题色 | `#142A50` |
| 辅助色 | `#36D6E7` |
| 浅背景 | `#F3F8FF` |
| 正文色 | `#26344A` |
| 字体与字重 | 按 V2.0 规范，整套统一 |
| 卡片、圆角、边框、投影 | 按 V2.0 规范，保持组件语言统一 |
| 图标与图形质感 | 现代、简洁、风格统一 |
| 页面布局 | 根据内容选择或组合 V2.0 布局 |

**优先级：用户明确的项目视觉要求 > V2.0 默认规范。**

- 用户明确要求以某份实际文件作为视觉参考时，记录参考文件、版本、具体要求与适用范围，再据此设计；不能仅因其存在于内容知识库中就自动采用其美术风格。
- 指定参考文件不可访问或参数无法核实时，注明具体缺项，不猜测、不宣称已经匹配。未获得其他明确要求前，以 V2.0 为可用默认值。
- 整套保持统一设计语言，不能随意拼接不同参考文件的颜色、字体和组件。
- 单页可以在同一色彩体系内做明暗变化，例如封面深色反转，并在逐页依据中说明；跨体系更换须有明确项目要求。
- V2.0 的尺寸与间距属于参考规范，按真实画布和可读性调整，不机械限制特殊页面。

## 三、素材声明规则

| 素材 | 使用规则 | 必须记录的信息 |
|---|---|---|
| 历史 PPT 内容 | 可引用业务事实和结构；不默认照搬其美术表现 | 来源文件／页码（可追溯时） |
| 真实产品截图 | 优先使用真实截图；不得将概念图冒充已上线功能 | 产品／版本、截图来源 |
| AI 生成图片、3D 场景 | 可用于概念表达；**不能冒充真实项目照片、已建成效果或真实系统界面** | 标记“AI 生成／概念示意” |
| 外部照片、插画、图标 | 核实使用权限；风格与整套 PPT 一致 | 来源、授权状态（已确认／待确认） |
| 架构图、流程图、数据图 | 优先使用可编辑元素；连接关系、数值必须有依据 | 数据／业务依据，是否可编辑 |

**声明方式：**素材来源记录在页面设计备注、元数据或旁附的逐页依据中，不必在正式演示页堆放声明文字；但凡容易被误认为事实的概念图，应在展示语境中明确写明“概念示意”。来源或授权不明的素材不得标记为“已获授权”。

## 四、逐页设计依据模板

每页只保留必要信息，不编写长篇设计报告。推荐使用如下模板：

```yaml
页码: P08
页面类型: 总体架构页
视觉基准: V2.0默认规范  # 用户指定视觉参考时填写实际文件及适用要求
布局: 分层架构 + 局部中心强调
视觉主体: 核心平台模块（2.5D轻立体）
视觉处理: 浅背景、柔和投影、少量强调色；控制装饰
设计理由: 分层体现上下关系，突出核心平台，保证架构可读性
素材说明: 架构内容来自项目资料；图标为自制矢量；无虚构数据
验收结果: 待验收  # 仅渲染并检查后填写：通过 / 待修改
```

> 特殊情况只补充必要说明，例如：跨页风格变化原因、用户指定参考文件的参数来源、概念图标识、素材授权待确认。**未经实测不得填写“通过”。**

## 五、逐页视觉验收清单

| 检查项 | 通过标准 |
|---|---|
| □ 构图与焦点 | 视觉重心明确，观众能快速发现页面核心信息 |
| □ 信息层次 | 标题、主要内容、辅助说明的字号与视觉权重分明 |
| □ 排版与留白 | 元素对齐、间距协调，不拥挤、不机械填满页面 |
| □ 视觉质感 | 渐变、阴影、圆角、图标、3D等精致且克制，不堆砌特效 |
| □ 逻辑可读 | 架构层次、流程方向、数据关系准确且容易辨认 |
| □ 风格一致 | 色彩、字体、组件、图标遵循全套选定的视觉基准 |
| □ 页面变化 | 不机械连续重复相同卡片布局；变化应有内容依据 |
| □ 素材真实 | 图片与截图身份明确，概念示意不冒充实物，来源可追溯 |
| □ 渲染完整 | 无文字溢出、重叠遮挡、裁切、字体缺失、图像模糊等问题 |

### 验收裁决

- **硬性不通过：**文字溢出／元素重叠、核心信息不可读、架构或数据错误、素材误导、明显违反既定视觉基准。出现任一项，必须修改。
- **设计待优化：**页面拥挤、视觉中心不清楚、组件粗糙、装饰过多、缺少必要留白或整套页面严重同质化。应调整后重新查看渲染结果。
- **通过：**硬性问题全部消除，且构图、层次、留白、质感与统一性达到正式商业演示水平。

**验收对象必须是实际渲染的每一页。** HTML提交确认前先进行浏览器逐页检查；可编辑PPTX生成后再次进行独立逐页渲染检查。HTML确认不代表PPTX已经验收。如果不能渲染或无法检查，应记录“未完成视觉验收”，不得默认通过。

## 六、与 V2.0 的关系

- **《AI PPT 高级视觉设计知识库 MVP V2.0》：**定义“怎样设计更美观”，包含五层视觉结构、布局、3D、光影、配色与动效标准。
- **本文件：**只解决“参数用哪套、素材如何声明、每页为什么这样设计、怎样判断成品合格”。
- **既有 PPT 内容知识库：**继续解决“应该讲什么”，不承担审美基准职责。

**最终执行准则：内容取自知识库，视觉遵循 V2.0，成品按本清单以实际渲染效果验收。**
